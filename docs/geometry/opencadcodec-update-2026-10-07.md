## Public-model audit

- `EntityCommon.layer_handle` is a new Serde-skipped optional source handle. It distinguishes a true layer 0 from the DWG reader's unresolved-reference fallback. Supported OCDraw native content is diagnosed/skipped when unresolved; typed spline capture retains the handle and leaves native layer absent. Known source name/handle contradictions are structurally rejected. IFCCAD rejects unresolved/inconsistent layer references. Resolved native layer associations reconstruct new handles rather than replaying source identities.
- `Spline.dwg_scenario` is new Serde-skipped optional source state. It records control-point versus fit-point storage, including limits on which closure/periodicity flags were actually present. The spline snapshot captures it explicitly without inventing geometric semantics.
- Newly captured `openaec.opencadcodec.spline` payloads use version 2, requiring explicit nullable `dwgScenario` and `common.layerHandle`. Version 1 at the previous audited revision remains readable/restorable, with unavailable new source state represented as None. Source revision, envelope payload version and body revision must agree. Unknown providers/core transport are unchanged.
- New table overrides, associative/count/solid-history operations and ACIS details stay inside already unsupported entity/object families, with the existing exhaustive inventory classification and residual loss checks. There are no new native families, schemas or conformance changes. Block-record changes provide legacy unit transport helpers; native block units remain subject to the existing converter contracts. Generic Polyline3D fit-code mapping improves codec fidelity but does not authorize fit/spline-fit native semantics. Newly emitted canonical INSERT-count framing is qualified against the inverse handle list; unfamiliar or mismatched bytes retain source-loss evidence. Typed common/marker/workspace comparisons exclude layer handles only after their association is qualified.
- Codec dependency changes are the upstream 0.6.0 graph (foldhash and thiserror 2); no unrelated dependency upgrade or source-cache patch is introduced. The ignored lock/configuration records the selected verification graph.
