# IFCCAD 2026.45.1 alpha

**Native core source alpha — 4 November 2026.** Tag: `v2026.45.1`.

This release combines shared annotation contexts and exact font/SHX source
requests. Text/MText, Dimensions, Hatch and block references retain their
supported saved scale/view records independently of base drawing values.
Named scales keep their identity even when their numeric ratios are equal;
explicit disabled modes and saved drawing/layout scale policies remain distinct.
All nine Dimension kinds can retain separate context points and saved pictures.
This stores authored contexts; it does not add a general association engine.

Font requests retain family, CAD primary/Big Font names and qualified face
metadata. SHX sources keep a portable basename plus an optional exact authored
`cadFileName`, including relative, drive-relative and absolute requests.
Same-named source records remain independent, including unused records and
shared marker bindings. Missing external files are valid; broken internal
references are rejected. No external lookup, embedding or portable origin/hash
contract is added. Application availability is separate from native storage.

## File contracts and compatibility

- IFCX syntax: `ifcx_alpha`; native profile **0.5.0**, import
  `urn:example:ifccad:0.5.0`.
- Standalone CBOR: mapping revision **5**.
- Optional CBOR + Zstd: transport revision **1**, inner mapping **5**.

The preceding published release 2026.45.0 used profile 0.3.0/CBOR3. Unpublished
annotation draft 0.4.0/CBOR4 and font draft 0.5.0/CBOR5 are delivered together here;
there is no intermediate 0.4 release. Current readers reject unsupported profile
and mapping identifiers. Historical readers/migrations are not included.
Released conformance collections and previous tags remain immutable.

## Shared exchange and Explorer

The official Document PR #11 merge `47031369d9d2bf8b192c508e31e772b41bb2b990`
contains both accepted contributions and has the same source tree as the tested
resource head 044bfcb7. Later Document-main/codec work is outside this bounded
adoption. The exact codec 4018037d remains explicitly pinned through its existing
fork URL to keep Document and kernel on one model; that commit is also contained
in official codec merge 0907cc78. The host uses Studio 3d2c1bf4, kernel b2656bd and
compatible native core 0e8f5e61, whose logical core matches this release.

Explorer and its embedded host use the same profile and official Document merge.
The existing catalogue and house examples are migrated without adding panels.
The inspector includes authored requests in saved context MText and reports
availability separately. Source requests are not rewritten to resolve fonts.

Acceptance includes one compact gallery and sample_AC1032, strict native
readback and physical AC1032 DWG/ASCII DXF/binary DXF resource projections.
Existing unsupported sample semantics remain diagnosed. Local host smoke covers
a representative text property edit and anchor grip with undo/redo and dependent
text display. Whole-drawing losslessness, full glyph fidelity and all annotation
editing are not implied. The general saved-picture editing issue OCS #2325 remains
separate. Missing fictitious gallery SHX files intentionally produce warnings.

## Native artifacts and verification

Attached `.crate` and deterministic source archive contain the native core,
schemas, tests, examples and documentation with registry-only dependencies and
an isolated native lockfile. They exclude Document, CAD runtimes, viewer/browser,
Explorer, archived converters and local patches. No crates.io publication or
prebuilt native binary is included. GitHub's automatic repository snapshots
have broader scope than these native artifacts.

The final candidate is verified with the workspace gate, optional Zstd,
release-tool and frontend tests, production browser readback and the matching
host/browser build checks. The native package is separately built and tested
with Rust 1.98.0 on Windows x86_64 MSVC. No corpus sweep or size benchmark is part
of qualification. Explorer deployment is a separate application delivery beside
the native artifacts and is gated by its build and public deployment smoke.

`release-manifest.json` records source revision, commands and artifact hashes;
`SHA256SUMS` covers it and both native artifacts. `SOURCE-MANIFEST.json` inside
the archive records source hashes and format identifiers. Published artifacts
and tags are immutable.
