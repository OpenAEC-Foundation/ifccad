# IFCCAD 2026.45.0 alpha

**Native core source alpha — 2 November 2026.** Tag: `v2026.45.0`.

This release adds finite signed extrusion thickness to Point, LineSegment,
Circle, Arc and PlanarPolyline, including saved Dimension graphics. LINE retains
scope-space endpoints and a separate unit extrusion direction. Placed primitives
sweep along their stored axes' cross product; native IO does not normalize the
authored state. Polyline widths and presentation lineweight remain independent.

Native JSON/CBOR retain exact values, including negative zero, and omit only
intrinsic positive-zero defaults. Shared validation and outward bounds account
for positive, negative and oblique sweeps, preserve partial evidence and reject
overflow atomically. Selectors and clipping continue to use the base contour.

## File contracts and compatibility

- IFCX syntax: `ifcx_alpha`; native profile **0.3.0**, import
  `urn:example:ifccad:0.3.0`.
- Standalone CBOR: mapping revision **3**.
- Optional Zstd: transport revision **1**, inner CBOR mapping **3**, disabled by
  default through feature `ifccad-cbor-zstd`.

Profile 0.2.0 and CBOR 2 from 2026.44.1 are superseded by the active reader. No
historical reader or migration is provided. Earlier tags and numbered conformance
collections are unchanged. Keep original drawings. Alpha releases have no general
backward-compatibility guarantee; unchanged Zstd framing does not imply inner
format compatibility.

## Conversion and application boundary

The repository pins official opencaddocument PR #8 merge
`28f1ad1214816e6b5c21162b732df0604bdf38bd`, with codec
`0a5542baa6052a2b07fc700b7ba041549650a997`. Document uses compatible core
`07e1ef1c4e975afcab0a07012bed8a82a56202cb`. These are source dependencies,
not components of the attached native package.

The paired mapping retains thickness for the five primitive families and imports
ordinary unfitted classic 2D POLYLINE as PlanarPolyline with effective widths.
Original classic default/override presence is unavailable or unassessed in the
codec model; return uses equivalent LWPOLYLINE. Native Defaulted width export
reports materialization. Fitted/mesh/nonplanar vertex details remain diagnosed
omissions. See the [native profile contract](../../schemas/ifccad/experimental-contract-0.3.0.md).

Synthetic AC1032 DXF/DWG controls and a local Explorer preview were accepted.
The existing catalogue samples use 15 mm thickness with base Z=0. The separate
gallery is regression/review material, not an additional shipped example.
Explorer deployment is a separate application delivery alongside the native
release, with browser/host build checks and no application files in the native artifacts. Circle/Arc display is
tracked under OCS #2361; general rendering, associative regeneration and
editing/undo behavior are separate application responsibilities.

## Native artifacts and verification

Attached `.crate` and deterministic source archive contain the core, schemas,
tests, examples and release documentation, with registry-only dependencies and
a native lockfile. They exclude Document, CAD codecs, viewer/browser, Explorer,
archived converters and local patches. No crates.io publication or prebuilt
binaries are included. GitHub's automatic repository snapshots have a broader
scope; use the attached native artifacts for standalone reproduction.

The final candidate is checked with the repository gate, optional native Zstd,
release-tool tests, frontend regression tests and physical extrusion readback.
The isolated native package is built and tested with Rust 1.98.0 on Windows
x86_64 MSVC. This is source verification, not cross-platform binary qualification.
No practice-corpus or size benchmark is part of release qualification.

`release-manifest.json` records the exact source revision, commands and artifact
hashes. `SHA256SUMS` covers that manifest and the two native artifacts.
`SOURCE-MANIFEST.json` inside the archive records packaged source hashes and
format identities. Tags and published artifacts are immutable.
